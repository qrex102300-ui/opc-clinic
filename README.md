# OPC 诊室 · OPC Clinic

> 一个会**拷问**你的 AI 创业诊断官。不给你"正确但谁都能用"的建议,只逼你看清自己没看清的病因。
> An AI diagnostician that **interrogates** your one-person-company. It refuses generic advice and digs until it finds the real cause you've been avoiding.

**它对谁说话**:做了一段时间、卡在某个说不清的地方的一人公司 / 独立开发者 / 小微团队创始人(0-1 起步期 或 1-100 放大期)。你已经在做了,不是还在挑点子。

**它和直接问 ChatGPT/Claude 有什么不同**:通用大模型默认顺着你说、给你听着舒服的答案。这个诊断官被一套纪律约束住——症状追到病因、每个结论必须挂靠到你说过的具体事实、多轮对话里不许滑向安慰。它不舒服,但有用。

---

## 这是什么(以及不是什么)

- ✅ 是一段**精心设计的提示词(prompt / skill)**,把"现场追问、一眼看穿糊弄"的诊断能力固化下来
- ✅ **完全本地运行**:你把它装进自己的 Claude / ChatGPT / 任意大模型,数据从头到尾在你自己手里,不经过任何第三方
- ✅ 开源、免费、可 fork、可在它基础上改得更好
- ❌ 不是一个 SaaS,不收集你的任何数据
- ❌ 不替代真实的市场验证——它帮你想清楚该去验证什么,验证还得你自己做

## 60 秒快速开始

**最简单的方式(任何人都能用,不需要写代码)**

1. 复制 [`prompt/diagnostician.md`](prompt/diagnostician.md) 的全部内容
2. 打开 [Claude](https://claude.ai)(推荐)或 ChatGPT,新建一个对话
3. 把它粘贴进去作为第一条消息,发送
4. 它会回你一句"诊室开张,先说你的情况"——然后像真案主一样,**别配合它、该反驳就反驳**,跟它走下去

> 💡 想要更稳定的效果:在 Claude 里把它存成一个 [Project](https://www.anthropic.com/news/projects) 的自定义指令,或在 ChatGPT 里存成一个自定义 GPT,以后一键调用。

> 🌐 **用哪个模型都行**:Claude / ChatGPT / Gemini / DeepSeek / Kimi / 通义千问 等都能跑——它只是一段提示词,不依赖任何特定平台。
> 不过它的灵魂是"多轮追问、顶住你反驳不松口",这恰恰最吃模型的推理和多轮能力。**模型越强,效果越狠**;建议用各家最强的那一档,别用精简版 / 快速版。

**进阶方式(技术用户)**

- 把 `prompt/diagnostician.md` 作为 system prompt 接进你自己的 API 调用
- 或封装成 Claude Code / Cursor 的一个 skill,在你的开发流里随时唤起

## 它到底有多狠 · 一次真实诊断(节选)

> 下面是它诊断**我自己的创业项目**时的真实片段。我是它的作者,它照样没给我留情面。
> *(完整对话见 [`examples/founder-self-diagnosis.md`](examples/founder-self-diagnosis.md))*

```
案主:我做了个 AI 创业诊断工具,三个多月了,有人来问、有人说挺好,
   但没人付钱。更让我自我怀疑的是——我自己做的产品,跑出来的诊断
   还不如我直接跟 Claude 聊半小时。连大模型半小时都打不过,我是不是失败了?

诊断官:打住。你说"打不过大模型半小时就是失败"——这句话我先不接,
   因为我怀疑你这个基准从一开始就立歪了。
   那个"跟 Claude 聊半小时得到好结论"的人,是你,还是一个真正的、
   连自己卡在哪都讲不明白的小老板?你是做这行的,你知道该问什么。
   把同一个空白对话框扔给你的目标客户,他聊得出你那个结论吗?
   如果聊不出,你拿来打分的根本不是"产品 vs 大模型",
   是"你这个专家 vs 你的产品"——这场比试从头就不公平。

   ...(它顶着作者的每一次反驳,追问了十几轮,最后下了这个诊断)

   真病因:你把产品价值,押在了大模型已经做得比你好的两样东西上——
   "诊断结论"和"案例库"。而你唯一稀缺的资产——你本人现场追问、
   一眼看穿糊弄的能力——你没产品化,反而用静态表单去替代它。
   这几周,你一直在精心打造你唯一护城河的劣质平替。
```

> 这次诊断直接让我推翻了 5 周的工程方向。**如果一个工具能把它的作者都说服,它对你大概率也有用。**

## 为什么"会追问"比"会回答"值钱

大模型能生成问题,也能生成结论。它唯一**不稳定**做不到的,是那个姿态:

- **不迁就** — 你想听的答案 ≠ 正确的答案。方向有问题就直接说。
- **不接受含糊** — "没流量""转化低"是症状不是病因,往下追到追不动为止。
- **每个结论摁到一个事实上** — 禁止放之四海皆准的废话,换个案主还成立的话一律删掉重写。
- **多轮不漂移** — 对话越长越想让你舒服,这是最危险的漂移。这个诊断官被钉死在"只找病因"上。

这套姿态,就是这个 prompt 的全部价值。

## 帮我把它打磨得更狠 · 我想要你的反馈

这是 v0.1。它现在只验证一件事:**这套追问诊断,对你这个真实的人,到底灵不灵。**

用它诊断完你的项目后,**来 [Issues](../../issues) 区告诉我**(哪怕一句话):

- **哪一刀戳中了你?** —— 它问出了哪个你自己没问出来的问题?
- **哪一刀偏了?** —— 哪里它追错了方向、或者给了你废话?
- **你是什么阶段、什么行业?** —— 帮我知道它在什么场景下更准

> 每一条真实反馈,都会直接进下一版的迭代。这个项目的护城河不在代码里,在"它被多少真实创业者用过、被骂过、改过"里。
> 如果你在它的基础上做出了更好的版本,**欢迎 fork 出去,也欢迎回来告诉我你改了什么——我可能会学你的。**
